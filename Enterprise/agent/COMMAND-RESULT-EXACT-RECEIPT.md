# Exact command result ACK replay

The command queue still accepts one IN_PROGRESS → terminal transition only. An agent that loses the HTTP ACK after commit can now send the same normalized result again. The owning current enrolled credential is checked as before. A read-only, ownership-scoped SQL SELECT must prove terminal status, exact output/stderr, exit code and persisted completion timestamp. Comparison is case- and whitespace-sensitive in JS, not the database's default collation. A matching result returns the original completion time and duplicate=true, while conflicting/pre-claim results remain 409. The first write alone emits the completion audit. If the authoritative read fails, the result is not acknowledged; non-test modes cannot acknowledge from an in-memory shadow. The explicit test-only memory fixture is retained.

Tests cover exact retry, changed case/space, cross-device replay and unavailable/uncertain receipts. This is server receipt idempotency, NOT a durable agent retry outbox, execution redelivery, verified repair or a signed release. Do not re-execute uncertain commands. Persistent agent retry requires identity/origin-bound result rows, credential-safe resend and real offline/fault injection.
