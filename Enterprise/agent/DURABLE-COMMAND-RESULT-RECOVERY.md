# Durable command result recovery — combined #99 / #100 rehearsal

The v3 SQLite table uses a unique server command UUID and an HMAC binding of HTTPS origin, enrolled device/tenant/UID/hostname and current individual device credential. No raw credential or identity is stored in the delivery row. Old v2 UUID claims remain untouched and prevent re-execution; old unbound terminal results cannot be automatically replayed. A claimed-only row after interruption remains uncertain. An atomic single-row UPDATE persists the terminal result and delivery=pending together. The exact bounded, sanitized JSON result is stored as hex-encoded SQLite text, then sent without re-serialization (output deliberately limited to 1024 UTF-16 characters to stay within Windows sqlite3 CLI argument limits; longer output explicitly truncated). Never treat truncation or ACK as verified remediation.

Each normal/elevated or FlushOnly cycle attempts up to ten pending results with current matching binding. Read the active configuration and current enrolled token/identity before send; different origin, tenant, identity or rotated token quarantines previous rows. Captured token and HTTPS destination are used together; redirects disabled. Only a matching server receipt (boolean ok, matching UUID/status, valid completion timestamp, boolean duplicate) marks acknowledged. Transport errors, conflicts and malformed responses leave the same saved body pending. Acknowledged rows are retained to prevent command re-execution. No automatic replay of a command or guessed result. The integrated server receipt change (#100) returns exact persisted receipt without overwriting terminal state.

PowerShell native isolated fixture simulates committed-but-lost HTTP response, changed tenant, token rotation, origin change, malformed ACK and recovery without re-execution. Python real SQLite tests exercise concurrent claims, atomic result persistence, reopen, old rows and binding fences. These tests do not prove installed signed Windows MSI, packaged sqlite3 CLI, actual network partition/restart, secure concurrent setup/credential file updates or immutable OS-level storage ACLs. Full signed release, cross-installation identity/clone prevention, pending queue retention/backpressure and human reconciliation of old/uncertain/conflicting results remain required. No protected merge or deployment. This branch integrates #99 and #100 only, not #93 or #94.
