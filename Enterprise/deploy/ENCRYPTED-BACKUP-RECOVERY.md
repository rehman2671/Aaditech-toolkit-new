# Bounded encrypted backup recovery reference (LAN-08 / PR-007)

POSIX-only reference: AES-256-GCM with an externally supplied 32-byte random key, random 96-bit nonce and 128-bit authentication tag. Header (magic/version, installation UUID, backup UUID and nonce) is AAD. Single opaque nonempty file at most 64 MiB; not a full-size database backup format. Encrypt reads owner-only 0600 single-link file in existing 0700 trusted staging; returns unsigned canonical #104 manifest for independent signing. Recovery explicitly selects backup UUID and uses #104 independently pinned signature and installation ID checks, compares signed digest/size with exact ciphertext held in memory, verifies header identity and GCM tag before any plaintext file write. Exclusive temporary file, fsync and no-overwrite publication. Wrong key, tamper, existing outputs and unsafe staging fail. Synthetic crypto tests only. No network, key generation for deployment, live DB or restore execution.

Trusted installer lock/immutable staging and trusted ancestors are caller requirements. Never supply key in CLI args, logs or browser; independent key custody, rotation, nonce-use bounds, escrow, backup freshness/rollback and old-host fencing remain unimplemented. Process crash can leave private temporary data requiring operator recovery; JS buffer zeroing is best-effort, not guaranteed memory erasure. Recovered staging file is sensitive plaintext and not authorized for import. Windows ACL storage, streaming larger backups, actual database-consistent encrypted export, signer workflow, physical offsite restore and clone isolation still pending. DEC-001 open.
