# Installation identity reference contract (PR-004 / LAN-05)

Stack owner decision DEC-001 remains open. This is a stack-neutral planning contract and a POSIX reference private-file adapter; it deliberately does not modify the deployed MySQL backup/restore scripts, select the final database schema, or imply Windows support.

The record contains only schema_version=1 and a canonical random UUID v4 installation_id, independent of device/user/tenant identifiers. Fresh initialization is allowed in the reference store only when caller-observed database, credentials and service are explicitly absent and the identity file is absent. Unknown or existing state is a hard refusal. POSIX storage requires an existing owner-only 0700 directory, a 0600 regular single-link identity file, no symlink path, fsync and no-replacement publication by hard link. An interrupted publication can leave a private orphan or a multi-link identity, requiring manual inspection rather than rotation. An existing record is never overwritten. Callers must hold a trusted deployment lock, control the directory/ancestors and independently observe actual resources; the input facts are not proof. This module has no installer entrypoint.

Reconfigure preserves the ID when existing database and credentials are present. Restore-as-same requires a matching backup ID for an existing target or an explicit old-instance fencing planning input for an empty target. All plans expressly say mutation_authorized=false: authenticating an encrypted backup, verifying its digest/manifest, verifying fencing and performing a serialized transaction are still necessary. Clone-new is blocked until independent new identity, tenant/device namespace isolation, credential/key rotation and review are implemented. No copying of production backup secrets into a new office.

Tests exercise real temporary filesystem, concurrent no-overwrite initialization, corruption/symlink/permission denial, unknown resource state, cross-installation mismatch and clone default-deny. Windows ACL-backed adapter, runtime/DB identity, signed backup manifest binding, physical restore/clone acceptance, installer and migration integration are pending. Never treat this reference implementation as completing PR-004 or LAN-05.
