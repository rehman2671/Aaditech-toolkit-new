# Phase N Stage 31 — Deployment and Signed Publication Preflight

**Status: CODE PROPOSED; PR/main CI PENDING; CUSTOMER PRODUCTION BLOCKED.**

## Failure mode and security boundary

Stages N27–N30 established durable telemetry ACKs, atomic server-side batch
replay protection and Windows MSI queue preservation in disposable CI. However,
Hostinger host/server details and public signing approval have deliberately not
been finalized; no CI job may pretend those external resources are accepted.
A manually selected signed CI run also needs an independent operator-approved
source commit and MSI checksum, not only a self-reported downloaded manifest.

## Stage N31 implementation

1. New `Enterprise/deploy/preflight-stage31.sh` calls existing N14 private
   .env checks; writes a redacted, permission-600 JSON report only to a NEW
   explicit path, and does **not source** .env or print credentials. It never
   deploys. Public network access occurs only with BOTH `--live` and
   `--confirm-live PROBE_PUBLIC_HEALTH`, reusing the existing Hostinger
   TLS/redirect/healthy-MySQL read-only checker. Any report always indicates
   external approval is still required.
2. New `Enterprise/tests/Test-CustomerWindowsAcceptance.ps1` runs READ-ONLY
   on the actual client machine, reports configured HTTPS endpoint shape,
   identity/token file presence (NOT contents), NETWORK SERVICE scheduled
   task principal, installed worker, sqlite3.exe and persistent queue
   integrity/lifetime UUID. Optional `-NetworkProbe` makes only an anonymous
   HTTPS GET /healthz; optional approved publisher pin validates trusted,
   timestamped Authenticode signature on the installed EXE. It cannot claim
   physical ACK-loss evidence, signed MSI publication, backups or live
   integration completion.
3. Protected manual workflow `publish-signed-installer.yml` now demands
   additional `approved_source_sha` and `approved_msi_sha256` fields.
   The verified manual successful same-repository main CI run must match the
   independently reviewed source commit. Published MSI actual disk SHA-256
   and SHA256SUMS manifest must BOTH match the independent human-approved
   MSI hash; existing CA/signer thumbprint, timestamp and embedded EXE
   checks are preserved. No secrets or signing material are generated by CI.
4. Automated negative tests cover missing/unsafe private config, offline
   no-network behavior and redacted report, unprovisioned Windows fail-closed
   result, and fake unsigned MSI mismatched/malformed approved hash.
   No actual public GitHub Release or customer deployment is triggered.
