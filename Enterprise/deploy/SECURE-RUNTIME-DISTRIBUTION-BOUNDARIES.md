# Non-test secure distribution and session boundaries — review proposal

**Scope:** In the existing public-DNS/ACME deployment profile, `NODE_ENV` missing/development/staging must not fall into synthetic agent setup, HTTP session, or legacy root-CA trust. No LAN installer, CA service, signed MSI or production acceptance is created here.

Before this patch, `agent-origin.js` only honored operator-owned `SERVER_HOST` + HTTPS if `NODE_ENV=production`. Any other runtime trusted the caller's Host header when generating downloadable agent scripts/JSON; an attacker who can influence the request host could poison enrollment URLs. `agent-artifacts.js` could also generate a private test root CA, and `/api/ca.crt` could distribute it. Browser login/workspace cookies were issued without `Secure` outside exact production, and user creation allowed a fixture fallback password.

**Default-deny policy:** Only `NODE_ENV=test` may use loopback/HTTP fixture origins, auto-generated test CA, the legacy test root download, insecure cookie flags, and synthetic user passwords. All other runtimes must use operator-controlled public `SERVER_HOST` over HTTPS; missing/invalid host returns `AGENT_ORIGIN_NOT_CONFIGURED`, never a request host fallback. Legacy CA distribution returns HTTP 410 and certificate generation is disabled outside tests. All six session cookie flags are `Secure` in non-test modes; creating a user without a password returns `EXPLICIT_PASSWORD_REQUIRED`. The bootstrap response similarly uses the operator-owned `SERVER_HOST` outside tests.

**Acceptance limits:** this code preserves the current **public DNS** profile; it does NOT add intranet certificate SAN handling or local CA trust. LAN installer [#80](https://github.com/rehman2671/Aaditech-toolkit-new/issues/80) requires a separately designed, reviewed TLS/PKI profile and original architecture decision [#79](https://github.com/rehman2671/Aaditech-toolkit-new/issues/79). Do not weaken public-DNS validation to accept a local IP as a shortcut. All deployed browser sessions must be served over valid HTTPS after this change; HTTP staging workflows may intentionally stop working. Do not set `NODE_ENV=test` on deployed servers.

Tests add non-test Host injection/HTTPS and missing SERVER_HOST rejection, no production-like CA creation, HTTP 410 for legacy CA routes and source contract checks for secure cookies/explicit passwords. This PR does not independently sign an installer or prove physical LAN acceptance; all changes await owner/security review, exact-head CI and protected signing governance #62.
