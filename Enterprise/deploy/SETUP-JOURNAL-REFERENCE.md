## Independently pinned checkpoint verification

`inspectAnchoredSetupJournal` verifies an externally signed canonical UTF-8 JSON record (one trailing LF, exact field order: schema_version, installation_id, release_sha256, sequence, record_sha256). The caller supplies the current exact checkpoint SHA-256 and Ed25519 public-key SPKI SHA-256 from independent trusted custody, plus the detached 64-byte signature and public PEM. A checkpoint must refer to a nonempty journal. Wrong digest/key/signature, foreign binding, noncanonical bytes, truncation, full rollback and an advanced local head are rejected. A matched pending STARTED still requires reconciliation and cannot authorize execution.

The verifier does not generate or manage external checkpoints, authenticate the source of caller pins, establish freshness of replayed pins, lock the journal, or update remote custody atomically. If the external anchor is stale or compromised, rollback may go undetected. Caller must independently protect and advance the current anchor, serialize actual operations and reconcile crash windows; no automatic replay or setup approval. POSIX reference only, no Windows ACL or runtime adapter.
