# Bound employee reporting — source candidate

Prerequisites: approved DEC-001 runtime, persistent MySQL migration 021, independently provisioned owner-only POSIX identity directory and pins, quiescent new DB with no enrolled devices or troubleshooting history. No auto adoption, no full freshness proof, no cloned DB fencing. Configure trusted server environment: AADITECH_BOUND_REPORTS=enabled, AADITECH_IDENTITY_DIRECTORY, AADITECH_INSTALLATION_ID, AADITECH_IDENTITY_SHA256. On a quiescent loopback MySQL target only, local operator CLI: node scripts/bind-fresh-database-identity.mjs --bind-empty-database, with DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME securely supplied. Never pass secrets in command arguments. Not an approved production setup procedure.

The portal Troubleshooting Help page offers separate report-only controls to MONITORING users and assignment controls to SUPER_ADMIN. The existing service requires persisted active primary-tenant roles. Exact device UUID and employee ID must come from approved administration records; assignment ownership must be verified by the operator. No automatic regrant after revoke.

Endpoints (explicit Bearer and no-store): GET /api/v1/troubleshooting/employee-devices; POST /api/v1/troubleshooting/employee-binding with exact JSON deviceId, employeeId, action, confirmation (GRANT/REVOKE and CONFIRM_GRANT_REPORT_ONLY/CONFIRM_REVOKE_REPORT_ONLY); POST /api/v1/troubleshooting/employee-report with deviceId, requestId, categoryId, hazard, consent (SUBMIT_REPORT_ONLY). No caller installation or tenant override. Disabled/mismatched identity blocks. The service rechecks persistent binding in the business transaction. Exact in-page retry preserves ID; closing page loses local retry data, contact IT with request ID for uncertain outcomes. No diagnostic/repair or verified-resolution authority.

Regression: migration 021/baseline/order, local identity mismatch, occupied refusal, repeat binding, same-transaction recheck, real temporary-table SQL rehearsal, HTTP unauthorized/cross-tenant/revoked/replay, UI category/consent/session and assignment flows, persistent DB restart/restore and independent physical approval. No production acceptance.
