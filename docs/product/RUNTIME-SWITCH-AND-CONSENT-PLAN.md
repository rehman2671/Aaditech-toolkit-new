# Runtime file switch and consent-bound review plan — source candidate

## Local runtime configuration switch

Requires Linux, exclusive operator custody, quiescent dependent services, a private 0700 directory, private 0600 active .env and .env.candidate, independently recorded hashes, and a separate empty private setup lock root. Use node scripts/switch-runtime-configuration-cli.mjs --switch-runtime-configuration with bounded JSON stdin: confirmation SWITCH_CONFIGURATION_FILE_ONLY_SERVICES_QUIESCED, operation activate, profile (node or compose), activePath, lockRoot, originalSha256, candidateSha256, changes (same exact fields as candidate creation). Original bytes copied to .env.previous-<originalSha256> before replacement; no overwrite. To roll back, same pins and changes, operation rollback and confirmation RESTORE_CONFIGURATION_FILE_ONLY_SERVICES_QUIESCED. The active file must match the candidate and backup must match original. Both operations return redacted digest receipt only. Recovery files contain secrets: never display, share or commit them. A failure can leave lock/backup/candidate/replacement; keep services stopped and reconcile manually. No automated service stop/start, TLS or DB continuity proof, installation acceptance or crash-recovery automation. Do not use on production without reviewed deployment procedure.

Requires migrations 019, 021, 023, current granted nonexpired REVIEW_ONLY consent, persisted tenant SUPER_ADMIN and active employee assignment. GET /api/v1/troubleshooting/diagnostic-review-plan?incidentId=...&deviceId=...; POST exact incidentId, deviceId, requestId, expectedConsentRevision, confirmation CONFIRM_REVIEW_PLAN_ONLY. The technician consent page offers Check plan and explicit Record plan. One catalog-derived plan per incident; exact retry requires matching actor/request and audit binding. Legacy unbound plan conflicts instead of adopting. Grant revocation or expiry blocks access/planning; no dispatch, credential or evidence authorization. Actual collection and independently verified results remain pending. Real HTTP/MySQL and physical acceptance required.
